# 시연 영상 순서 (약 5분)

## 촬영 전 준비

1. `backend/.env`: `LLM_PROVIDER=vertex`, `IMAGE_PROVIDER=vertex`
2. 백엔드 `cd backend && uv run uvicorn app.main:app --reload`, 프론트 `cd frontend && pnpm dev`
3. `curl localhost:8000/api/health`로 모델 이름 확인
4. 리허설로 한 번 끝까지 돌린 뒤, 잘 나온 이미지를 풀에 저장해 둔다
   `cd backend && uv run python scripts/save_pool.py <run_id>`
   → 촬영 중 이미지 생성이 실패하면 `IMAGE_PROVIDER=pool`로 바꾸고 그 Pod만 다시 생성
5. 브라우저 창 너비를 넓게, 확대 비율 90% 정도

## 장면

| # | 화면 | 말할 내용 |
|---|---|---|
| 1 | `docs/plan.md`의 흐름도 | 1~8주차 프롬프트를 한 흐름으로 연결, 단계마다 AI가 3안을 만들고 사람이 고른다 |
| 2 | 입력 폼 작성 → 시작 | 타겟, 무드, 이미 쓴 1순위 Pod, 스펙. 스펙에 적은 것만 카피에 쓰인다 |
| 3 | ① 생성 → 3안 비교 → 선택 | 안마다 방향이 다르다(관심사 / 무드 / 구매 흐름). 레이아웃 규칙은 코드가 검사해 경고로 보여준다 |
| 3-1 | "순서 · 레이아웃 직접 바꾸기" → 블록 끌어서 순서 변경, 레이아웃 바꾸기 → 저장 | 사람이 블록처럼 고칠 수 있다. 같은 레이아웃이 연속되면 바로 빨갛게 표시되고, 저장하면 서버가 같은 규칙으로 다시 검사한다 |
| 4 | ② 생성 → 경고 있는 안 가리키기 | 글자 수·헤드카피 유형·어미 배열·팩트체크 근거를 코드가 검사한다 |
| 5 | ② 선택 → "Pod별 수정 요청"에서 Pod 하나 고르고 요청 → (또는 "선택한 카피 직접 수정하기") | AI에게 Pod 하나만 고쳐 달라고 할 수 있고, 직접 고쳐도 된다. 어느 쪽이든 같은 규칙으로 다시 검사한다 |
| 6 | ① 다른 안 선택 시 확인창 | 앞 단계가 바뀌면 뒤 단계는 초기화된다 (보여주고 취소) |
| 7 | ③ 생성(Pod별로 차례로 나타남) → Pod별 선택 | 이미지는 Pod마다 고른다. 공식 제품 사진을 참조로 보낸다. 이미지에는 글자를 넣지 않는다 |
| 7-1 | 이미지 한 장 "이 이미지 수정 요청" → "배경을 밤의 도시 야경으로" | 그 이미지만 고친 새 안이 추가되고, 제품 모양은 그대로 유지된다 (약 1분) |
| 8 | ④ 조립 → 미리보기 스크롤 | HTML은 LLM이 아니라 P3 규칙을 옮긴 템플릿으로 조립한다 |
| 9 | `docs/submission.md` 기술 스택 표 | 외부 API 불가 → 회사 GCP Vertex, 실측으로 고친 것(멈춤·속도·헤드카피 길이) |

## 실패 대비

- 생성 버튼이 오래 걸리면: 요청마다 45초 제한 후 자동으로 한 번 더 시도한다. 그래도 실패하면 오류 문구가 뜨고 다시 생성하면 된다.
- 새로고침해도 주소의 `?run=`으로 진행 상황이 그대로 남는다.
